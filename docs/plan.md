# 기획서

작성일: 2026-08-26  
상태: 확정  
원본: 사용자 대화 및 첨부 이미지 2장

## 목표

성인 발달장애인이 자신의 생활 할 일을 직접 만들고 체크하며, 필요한 일정만 지원자와 함께 관리할 수 있는 모바일 앱을 만든다.

## 범위 원칙

- 당사자가 계정과 일정의 주인이다.
- 쉬운 모드와 일반 모드는 동일한 데이터·기능을 사용하고 표현 밀도만 다르다.
- 지원자는 일정 관리를 돕지만 완료를 대신 기록하지 않는다.
- 약 기능은 사진·표시 이름·알림 시간·반복·복용 기록만 다루며 복용량이나 치료 판단을 하지 않는다.
- 미완료를 실패, 벌점, 순위, 연속 기록 초기화로 표현하지 않는다.

## 기술 구성

- 화면: React Native + Expo + TypeScript
- 스타일: React Native 디자인 토큰(`src/frontend/theme/tokens.ts`), 라이트·다크 모드
- 데이터: Supabase 서울 리전(Postgres, Auth, 비공개 Storage), 모든 노출 테이블에 RLS 적용
- 알림: Expo Notifications의 기기 내 예약 알림, 공유 일정 변경 시 필요한 경우에만 원격 알림
- 배포: GitHub 연동 Vercel 정적 웹 배포와 설치형 PWA. Android·iOS 네이티브 배포는 후속 선택지

### 선택 근거

- 모바일 우선 PWA: GitHub에서 Vercel로 빠르게 배포하고 홈 화면에 설치할 수 있다. 단점은 알림·사진 같은 기기 기능이 네이티브 앱보다 제한될 수 있다는 점이다. 실제 사용성 검증 뒤 필요하면 EAS Build 네이티브 앱으로 확장한다.
- Supabase: 지원자 공유와 사용자별 접근 제한을 한 서비스에서 구성할 수 있다. 단점은 외부 클라우드 의존, 사용량 증가 시 비용, 출시 전 개인정보 검토가 필요하다는 점이다. 차선책인 기기 저장은 단순하지만 일정 공유가 불가능하다.
- 외부 데이터·AI·결제 API는 사용하지 않는다.

## 기능 세부 결정

### 일반 할 일 편집

- 기본 예시: 운동, 양치, 머리 감기, 체중 기록, 약 복용
- 당사자는 모든 할 일을 직접 추가·수정·삭제·정렬할 수 있다.
- 반복 할 일 수정 시 `오늘만 바꾸기 / 앞으로도 바꾸기`를 먼저 선택한다.
- 삭제 뒤에는 즉시 `되돌리기`를 제공한다.
- 지원자가 추가한 일정에는 작성자를 표시하고 당사자가 시간 변경·숨김·도움 요청을 할 수 있다.

### 복약 편집 안전선

- 당사자가 사진·표시 이름·알림 시간·반복 요일을 직접 편집한다.
- 앱에 복용량 계산·변경, 놓친 약 복용 판단, 증상 해석 필드를 만들지 않는다.
- 변경·삭제 전 `앱의 알림만 바뀌어요. 약 복용 방법은 의사·약사의 안내를 따라요.`를 보여준다.
- 완료 기록에는 실제 누른 시간을 자동 저장하며, 지원자가 완료를 대신 입력하지 않는다.
- 잠금화면 알림 기본 문구는 `확인할 일정이 있어요`다.

## 모듈 구조

- `src/frontend/screens/`: 설정, 오늘, 할 일 편집, 체중, 기록, 함께 관리 화면
- `src/frontend/components/`: 카드, 버튼, 격자, 알림, 확인·되돌리기 부품
- `src/frontend/theme/`: 라이트·다크 색상, 글꼴, 간격, 모서리 토큰
- `src/content/ko/`: 쉬운·일반 모드 한국어 문구
- `src/service/`: 인증, 할 일, 기록, 복약, 알림, 공유, 읽어주기 인터페이스
- `src/db/`: 타입, 스키마, 접근 정책, 저장소 정책
- `public/`, `vercel.json`: PWA 셸, 설치 아이콘, 오프라인 캐시, Vercel 빌드·SPA 라우팅

## 강화 후보

- 당사자 편집: 자신이 고른 색과 아이콘이 `내 일정`이라는 감각을 강화한다. 실제 사용성 검사에서 자주 고르는 조합만 기본값으로 다듬는다.
- 기록표: 빈칸을 실패가 아니라 `기록 없음/예정 없음`으로 구분해 부담 없이 다시 사용할 수 있게 한다.

## 견제 기록

- 반론자: 약 할 일을 일반 할 일과 완전히 동일하게 편집하면 안전 위험이 있다. → 당사자의 직접 편집권은 유지하되 복용량 기능은 제외하고, 약 관련 변경·삭제에 안전 확인과 변경 이력을 반영했다.
- 반론자: 첨부 이미지의 촘촘한 표를 홈에 옮기면 인지 부담이 크다. → 홈은 큰 카드, 격자는 별도 기록 화면으로 분리했다.
- 사용자대표(불편): 반복 일정의 수정 범위와 지원자가 만든 일정의 출처가 모호할 수 있다. → `오늘만/앞으로도`, 작성자 표시, 되돌리기를 반영했다.
- 사용자대표(호감): 직접 고른 색·아이콘과 주간 기록표가 자기주도감을 높일 수 있다. → 성인형 파스텔 디자인의 핵심으로 기록했다.
